# QModem逐项对照与通道一致性

审查基线：`c49654efc870f53712ee8e25bf181722eb1466d9`。参考[QModem源码](https://github.com/FUjr/QModem/tree/c49654efc870f53712ee8e25bf181722eb1466d9)，只依据公开协议事实独立实现Rust逻辑，不将Shell实现复制为插件后端。

## 协议实现

- 温度：按华为／鼎桥、移远、广和通、美格、Sierra、SIMCom、Telit、高新兴、富士康与Thales的型号及平台选择查询，注册89个身份。N510M与Air724UG在此基线没有可核验温度路径，保持未实现。
- 多种单位、传感器、备用命令分别处理；有效结果复用，备用只在没有有效主结果时执行。共享和独立模式使用同一套查询注册、低频调度、解析及时间戳校验，不让客户端连接数扩大AT查询量。
- Sierra EM9190、EM9291、MC7354、MC7355补模板锁频。读取固件的Available模板，不用预设型号名单冒充实时能力；保留其他制式掩码，失败不重放，也不自动飞行或重启。LTE型号默认进入4G选择，不留在空的5G页面。

## 不能只看函数是否存在

| 上游实际情况 | 本插件处理 |
| --- | --- |
| 华为vendor明确禁用LockBand、NeighborCell；部分辅助函数仍存在 | 不仅凭辅助函数打开全系列；既有MT5700专有协议不受此次禁用结论取代 |
| 美格vendor明确禁用LockBand、NeighborCell | 保留未实现／未开放状态，不编造其他厂商指令 |
| Sierra开放LockBand，禁用NeighborCell | 接入模板锁频；邻区继续受实际解析入口限制 |
| RG801平台锁频读写的上游分支不一致 | 不把LTE读取配上其他平台NR写入，等待可核验协议闭环 |
| SIMCom部分邻区依赖主动CNWSEARCH及等待流程 | 不能当成普通高频只读状态命令，需要独立的主动扫描调度及超时／占用测试 |

以上是代码审查范围，不代表厂商硬件永远不支持。待实现功能见[适配复查](RELEASE-AUDIT.md)，不能将未开放全部归因于硬件。

## 两种模式怎样保持一致

共享模式通过已核验QModem服务发送，独立模式通过自有空闲端点发送；协议注册、解析、能力门禁、确认与回读共用。回归用例让温度与Sierra模板分别经过Broker和IndependentSource实现的模拟端点，而非只给状态加一个shared布尔值。

共享服务版本仍有差异：数据库短信接口、事件和事务能力必须运行时协商；未提供时使用已有安全共享AT／队列路径，不能抢串口或升级他人的服务。短信索引、PDU分段、已读记录、事件优先与10秒兜底共用上层逻辑，但没有事件的服务不能宣传为零延迟。关闭收取与转发不保留收取任务。

## 验证边界

离线测试包括全部注册身份、两种通道、单位／传感器歧义、截断／错误回复、备用查询抑制、其他制式保留、写入失败和确认令牌不重放。所有hardwareAccepted仍为false：尚无逐型号／固件完整实机验收。构建与精确提交以Release为准，边界见[状态](STATUS.md)。
