# 性能与资源管理

本文描述1.0.0的资源控制方式，不以Rust语言、代码审查或单次内存快照宣称性能优势。正式制品尚无覆盖全部功能、模组和长期负载的统一CPU／RSS基准。

## 资源控制

- 一个后台采集器发布快照，客户端读取缓存，不按页面或客户端数量叠加AT采集。
- 可选查询各有刷新周期、有效期及失败退避。温度通常60秒刷新、90秒过期，有有效主结果时不发送备用命令；已有主状态命令可以复用。
- 正则惰性缓存，身份及能力展示复用已核验快照；写入仍重新核验。
- 请求线程池、消息、会话、回执、事件及队列均有上限。
- 短信与转发共用缓存；事件优先、无事件默认10秒兜底，没有事件能力时按截止点休眠，不每秒空醒。
- 两项关闭后释放短信收取／投递任务和可选事件／TLS资源；单独关闭转发不关闭用户开启的收取。
- 独立PDU增量每轮最多8个索引、10秒总预算；每模组最多128原始分段，最多16模组。投递与AT收取分离，有界合批，不为凑批次延迟。
- WebUI使用普通DOM／CSS，不依赖React、外部CDN或动画库，尽量复用节点，离页清理监听，支持减少动态效果。磁盘许可声明不由常驻服务加载。

## 如何评估

记录包摘要、模组／固件、通道模式、客户端数量、采样间隔和短信开关。区分主进程、临时子进程与整机CPU，不用页面整机CPU代表插件成本。比较空闲、周期读取、短信／转发和多客户端场景，观察RSS趋势、线程／句柄、接口延迟与错误率。

协议模拟、短观测与持续负载是不同证据。未测场景不填写“零占用”或性能提升百分比。
