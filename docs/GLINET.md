# GL.iNet 共享接口适配（开发中）

本页描述尚未正式发布的开发代码；已发布的1.0.9安装包不包含这些修改。不把Mudi7样本等同于GL.iNet全系列实机通过。

## 接入与发现

自动模式先保持既有QModem选择；无QModem时发现`modem.*.AT`服务及`get_result_AT`方法签名。按服务真实名称发现CPU或USB总线，不硬编码`modem.CPU.AT`，不根据路由器型号、接口编号或USB枚举顺序猜串口。没有此服务的设备仍走既有独立发现及占用保护；GL.iNet固件查询暂时失败时不自动抢占串口。

共享调用只提交`cmd`、`timeout`，核对`channel_status: true`、`data`、结束状态和已知回复标签，绑定ubus对象实例。禁止调用`update_AT_process`、`set_at_log_level`、切卡或飞行模式。有限缓存身份查询，错误冷却，无常驻辅助进程。服务实例变化或回复不完整时丢弃结果，不自动重发写操作。

模组身份使用同一QModem参考目录及已有解析器，不另建Mudi7型号名单。未收录型号仅提供通用有限信号，不宣称具有邻区、聚合或短信能力。传输适配不等于每个固件的AT格式、事件和写入事务均相同。

## 已有样本

用户提供的GL-E5800／Mudi7、GL版本4.10.0、定制OpenWrt23.05.4、RG650V-EU样本验证了服务方法签名、型号、服务小区、紧凑NR载波格式和短信模式／存储查询。紧凑载波带宽按该格式解码，不把未核实的末尾数值猜成SINR；SCC不借用PCC测量。只返回PCC时不冒充多载波聚合。

这些是接口及协议样本，不是插件安装后的在线验收，也不覆盖其他GL.iNet机型或USB模组的实测。

## WiFi

标准`network.wireless status`优先；缺少可用接口时，通过`iwinfo devices/info`读取真实AP运行态，再按显式ifname或唯一SSID与频段关联UCI。不能根据wlan编号或phy编号猜对应关系。映射存在歧义时只展示AP，不据此读取主网络终端或开放编辑。

展示与可编辑配置分开：2.4／5／6GHz的主网络配置可保留，关闭的访客配置不再隐藏主网络；运行状态不明时明确标记，不伪装已关闭或已开启。配置EHT160但运行接口报告HE160时并列说明，不仅凭配置声称正在WiFi7运行，也不据旧能力接口断言硬件不支持WiFi7。

原厂无法提供可核验的netifd配置到运行态关系时，WiFi仅只读；不擅自用原生reload替代未知厂商无线控制流程。6GHz与未知加密模式不冒充已有双频写入协议。

## 短信与写入边界

已知PDU模式可通过共享AT读取当前存储的完整快照，前后核对存储选择、模式与共享服务实例，复用插件已读、长短信重组、去重和PushPlus转发。普通列表查询可能影响模组的已读位，插件已读状态单独维护。不改CNMI、编码或存储。

尚无已核验的GL.iNet新短信事件接口；`sms_manager`只暴露日志设置不代表存在可复用收件箱。接收或转发开启时默认10秒兜底，沿用有界退避和缓存；两项关闭后无短信轮询工作线程，也不创建转发TLS客户端。未来事件接入必须单独核验，不能因CNMI存在就声称事件可用。

原厂提示符事务、短信发送／删除与锁定写入尚未核验，本适配目前限制为只读及收取／转发。相关写入能力不向客户端开放，也不能用AT危险开关绕过。缺失能力应明确反馈，不以识别到型号冒充全功能适配。

## 验收

离线回归覆盖目录内型号在CPU／USB共享传输上的选择、对象与方法约束、服务重启、空箱及合成PDU、存储变化、只读门禁、无线映射歧义和配置／运行态展示。仍需实际安装后验证信号、温度、邻区、真实短信、转发延迟及长期资源占用；这些不能由样本或模拟器代替。
