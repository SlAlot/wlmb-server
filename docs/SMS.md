# 短信与PushPlus转发

1.0.0的短信收取和转发开关独立，默认均关闭。插件入口为“短信→短信转发”；网络面板助手小程序入口为“设置→短信转发”。已读由插件维护，不把模组已读位当作转发状态。

## 时序与资源

事件优先，最多2秒通知合并预算；无事件默认每10秒兜底，可配置5–300秒，扫描完成后计时。短暂忙碌约5秒后恢复，其他失败递增退避。通道、模组查询、长短信重组及推送网络会增加延迟，不保证10秒内送达。

首次成功收取建立基线，不推送已存在的消息；重新开启不补推关闭期间的消息。空队列等待通知，有队列按期限唤醒；投递不占AT锁。两项关闭后释放可选线程、事件、队列及TLS客户端，其他设备采集继续运行。

PushPlus成功连续请求至少间隔13秒，首条不固定等待13秒。已排队的同模组短信可按正文大小合批，一次最多8条，不为凑批次延迟。成功数是服务接受的短信条数，不代表用户已收到。

## 共享模式

1.1.0起另支持GL.iNet共享AT的PDU收取和转发，暂不开放发送／删除及未经验证的事件，详见[GL.iNet适配边界](GLINET.md)。原厂CNMI、编码和存储均不改动；不能将QModem事务与事件能力直接套到GL.iNet。

核验QModem qmodem.sms v3及方法签名，按模组section绑定。数据库事件核对owner、端口、epoch和sequence，必要时有界跟进读取。兜底调用sync再读库，沿用原auto_delete策略，不修改配置。完整数据库ID与SIM索引隔离；删除前重核指纹，删除数据库记录不保证清理SIM副本。

managed发送使用唯一请求ID，未知或部分成功不重试。接口明确不存在或direct模式使用已核验共享AT／队列；已选数据库后出错不自动切换来源。不抢串口、不升级共享服务、不认领其他转发器的队列。

## 独立模式

自有Rust通道收取PDU或核验过的文本格式。CMTI索引提示可触发增量读取；提示不足、积压、过期、存储不匹配或没有基线时核对完整快照。每轮最多8个索引、10秒总预算；每模组最多128分段，最多16模组。格式不兼容时用安全快照，不盲改CNMI、编码或存储。

两种模式共用消息、已读、权限和转发逻辑，但固件能力必须运行时核验。eventConnected仅表示监听连接建立，不保证模组产生通知。

## 操作保护

发送／删除需要一次性确认、身份和指纹核对。单次发送最多70个UTF-16单元，不自动拆分收费短信。未知编码、未拼完、二进制或不完整回复不冒充正常消息；第三方并发修改不保证原子快照。

投递前持久化摘要预约，失败不发请求；结果未知不重放，重启也不重放未确认批次。Token保存在路由器私有目录，接口不回显；诊断和去重记录不保存号码、正文或Token。两个转发器向同一目标发送仍可能重复，不建议双开。

IMS配置、自动收取和转发不是同一开关。IMS仅对已核验协议开放，未知状态不当作关闭。实收／发送／删除／事件和推送送达须对应硬件验收，通用协议路径不等于全模组认证。
