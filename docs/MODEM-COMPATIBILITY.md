# 模组兼容与自动适配

1.0以QModem已审查基线为身份／协议参考，统一识别流程，不为每台DIY路由器写独立后端。路由器名称、系统、网络、WiFi来自OpenWrt本身，模组差异在协议层处理。

## 当前代码覆盖

逐项复查与缺项见[适配复查](RELEASE-AUDIT.md)；CI附带逐型号JSON，不把型号目录当作全部功能的硬件通过证据。

MT5700统一NR预设额外补充n3、n5、n8，标记reviewed-model-supplement；原QModem资料、SA／NSA分项及其他型号保持不变。预设不是固件实时能力或硬件驻留验证。

- 型号映射91个，基线USB／PCIe配置131份；同一厂商不代表同一平台。
- 信号解析入口已建立，具体信号／载波／邻区字段仍受协议和固件限制。
- 频段协议81型号、小区协议63型号；其余保持pending，不因版本1.0而全部启用。
- 模组温度注册89个身份，按厂商／平台解析；剩余N510M、Air724UG没有已核验路径。代码注册不是89个固件实机通过。
- 当前catalog中hardwareAccepted全为false：这不是所有真实设备都坏，而是没有全模组硬件验收证据，不能宣传全固件认证。
- 查询温度、签约速率、QCI、短信和IMS按实际能力门禁；标准PDU或模型清单不是短信硬件通过证明。

## 自动流程

设备树／系统信息 → USB／PCIe候选 → 接口占用与真实身份核验 → 型号／平台／协议 → 后台单采集缓存 → 按能力显示前端。

有QModem时优先核验共享服务，没有则识别GL.iNet原厂共享AT服务，再没有才使用自己的空闲通道。不得抢占拨号程序；未知接口或不确定回复停止危险写入。各通道复用模组协议逻辑，不依赖前端硬编码AT；GL.iNet当前的写入和事件限制见[专项说明](GLINET.md)。

前端不让用户猜模组指令。锁频优先可选频段，锁小区优先当前／邻区候选，仅补协议要求而缺失的项。候选n77／n78、CA中心频点、未知SCS不能直接冒充确定锁定信息。

## 新增模组的更新方式

运行上游审计，比较身份、平台、字段和命令文件哈希；维护者审查格式与安全语义后新增协议及离线样例。修改后检查共享／独立两种通道、缺失／截断／错误回复、占用变化、危险写入不重放及能力展示。

适配清单可用 `wlmb-server --catalog` 查看。[QModem参考](QMODEM.md)、[功能边界](FEATURES.md)、[发布标准](RELEASE-CRITERIA.md)。
